# 至商用版本的路线与验收

当前：v0.4.0 玩法原型。开发顺序由实现与测试结果决定，例行实现不等待用户确认。

## 已交付

- v0.1：单双人、随机平台、属性危险池、踏板、宝石和双出口。
- v0.1.1：分次踩踏板、明确过关条件，修复门锁体验。
- v0.2：菜单、存档、手柄映射、跳跃手感、模块拆分。
- v0.3：六关教学、随机机关、配色与合成音效、真实物理通关测试。
- v0.4：画面与 HUD、属性图案、粒子、音量和动态效果设置、指定种子。

## 下一阶段：可靠的试玩版（v0.5～v0.7）

1. 输入与设备：按键重映射、手柄断开重连提示、真实设备测试、控制器菜单操作；验收为键鼠和两个目标手柄均可独立完成教学。
2. 内容：增加真正需要合作的搬箱／连锁开关模块，单人提供可操作的顺序解法；验收为至少 12 个经过真人测试的模块、无已知软锁。
3. 路线：随机模式增加难度层级、短局目标、成绩与种子记录；扩展完整运动通关种子集并记录失败种子。
4. 体验：加入音量滑杆、局内教学提示、关卡选择、音效平衡与少量原创音乐；确认色觉差异和减弱动态设置可用。
5. 可靠性：存档版本迁移、异常写入、重启恢复、长时间游玩、不同分辨率与 Windows／Linux／macOS 的目标范围测试。

样章验收：20～30 分钟可独立试玩；陌生玩家无需口头教学；至少 10 名外部玩家反馈；多数玩家理解合作且愿意继续。达不到时先调整核心玩法，不直接扩大美术和内容投入。

## 商业品质样章（v0.8）

确定角色设定和统一美术，完成一个主题区域、反馈与声音。制作真实游戏画面的商店截图和短预告。核验所有字体、音乐、素材和依赖的商用许可；当前原创代码 MIT、字体 OFL 的许可文件必须保留。

原型截图和合成音效不等于最终商品品质；是否采购素材、雇佣外包等付费事项需要单独预算授权。

## Beta（v0.9）

目标 3～5 小时首次通关流程，关卡数量以体验验证结果为准。至少三个差异化主题、合作机关组合、结局、关卡选择和可选挑战。完整从头到尾体验、存档兼容、无已知崩溃和阻断通关问题。

首发范围：单人／本地双人。联网、创意工坊、编辑器和复杂装备暂不列为首发必需项。

## Steam 候选版（v1.0 RC）

- 确定首发平台、最低配置、控制器支持与语言范围，针对每个平台实际测试发布包。
- 核对当时 Steamworks 的开户、上架费、税务、商店审核与发行时间要求；使用用户自己的开发者账户和安全配置，凭据不进入仓库。
- 评估成就、云存档和 Steam Input 的实际必要性，按需求集成并验证离线启动、Overlay 和存档冲突。
- 完成中英文、隐私信息、许可列表、商店图片、预告、定价、支持入口和回滚流程。
- 冻结功能，集中修复缺陷；发布后保留首周快速修复能力。

当前没有 Steam 账户接入、商店页面或可发布包，不把工程版本号等同于商用就绪。

## 成本与市场验证

定价 28～48 元仅为初步研究区间，最终根据内容量、品质、竞品与玩家反馈决定。记录开发、美术、音频、翻译、推广和维护成本，以扣除折扣、退款、平台分成及税费后的单份净收入计算盈亏平衡。盈利无法由开发完成本身保证。

## 每次中间版本的门槛

1. 更新规则、已知问题和本文件中的实际进度。
2. 跑当前功能相关测试与完整回归，不能把零测试、未执行或失败描述为通过。
3. 核查工作区无临时文件、用户存档或凭据进入提交。
4. 提交 main，创建不可变的版本标签，给出 GitHub 源码 ZIP 下载链接。
5. 下载并在全新目录导入最终交付版本，验证恢复不依赖本机缓存。

源代码标签和下载包不依赖 GitHub Releases API，也不暗示已经发布到 Steam。
